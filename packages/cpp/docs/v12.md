# V12 RFQ integration (C++)

The websocket auction, as a C++ maker runs it. This page is the code;
[`docs/v12.md`](../../../docs/v12.md) is the protocol — the auction rules,
the error strings and the units — and each step below links back to it.

> Testnet (`Env::Testnet`) runs the strategies protocol, whose messages have a
> different shape. Everything here is what production (`Env::Mainnet`) runs.

## Setup

```cpp
#include <chrono>
#include <cstdlib>
#include <iostream>
#include <mutex>
#include <thread>

#include "ryskv12/client.hpp"
#include "ryskv12/nonce.hpp"

using namespace ryskv12;

const std::string MAKER = "0x…";   // the address of PRIVATE_KEY
const std::string ASSET = "0x…";   // the underlying you make markets in
const std::string USDC = "0x…";    // the chain's strike asset
constexpr std::int64_t CHAIN_ID = 8453;

Rysk sdk(Env::Mainnet, std::getenv("PRIVATE_KEY"));

// one per key, file backed: see Nonces below. Not thread safe, and the feed and
// /maker readers both draw from it, so guard it.
NonceCounter nonces;
std::mutex nonce_mutex;
std::string next_nonce() {
  std::lock_guard<std::mutex> lock(nonce_mutex);
  return nonces.next();
}

std::int64_t now_s() {
  using namespace std::chrono;
  return duration_cast<seconds>(system_clock::now().time_since_epoch()).count();
}
```

The key reaches the CLI through `RYSK_PRIVATE_KEY` in its environment, never
argv. No CLI yet? `sdk.setup()` downloads one.

## 1. Fund the maker balance

Premiums come out of the balance deposited with Rysk, not the wallet
([protocol](../../../docs/v12.md#1-before-quoting-funds)). Approving is an
on-chain call, so it is a one-off `run`; the deposit goes over `/maker`.

```cpp
Output approve = sdk.run(sdk.approve_args(CHAIN_ID, "1000000000", RPC_URL));
if (approve.exit_code != 0) throw std::runtime_error(approve.err);
```

```cpp
Process maker = sdk.spawn(sdk.connect_args("maker"));
std::thread maker_reader([&] { maker.read_lines(on_maker); });

Transfer deposit;
deposit.user = MAKER;
deposit.asset = USDC;
deposit.amount = "1000000000";
deposit.chain_id = CHAIN_ID;
deposit.is_deposit = true;  // false withdraws
deposit.nonce = next_nonce();
maker.send(sdk.transfer_args(deposit));
maker.send(sdk.balances_args(MAKER));  // answered on on_maker
```

`read_lines` blocks until the CLI exits, so every connection gets a thread of
its own. `send` is safe from any thread.

## 2. Listen for RFQs, 3. quote

One feed per asset, plus the one `/maker` connection. Each feed line is a
json-rpc message whose `id` is the RFQ id and whose `result` is the request
([protocol](../../../docs/v12.md#2-an-rfq-arrives)). Copy its terms into the
quote unchanged; only `price`, `nonce` and `valid_until` are yours
([protocol](../../../docs/v12.md#3-the-maker-quotes)).

```cpp
auto on_rfq = [&](const std::string& line) {
  auto msg = JsonRpcResponse::parse(line);
  if (!msg || msg->error) return;
  auto rfq = Request::from_json(*msg->result);  // nullopt: not a request
  if (!rfq) return;
  Quote q;
  q.asset_address = rfq->asset;
  q.chain_id = rfq->chain_id;
  q.expiry = rfq->expiry;
  q.is_put = rfq->is_put;
  q.is_taker_buy = rfq->is_taker_buy.value_or(false);
  q.strike = rfq->strike;
  q.quantity = rfq->quantity;
  q.usd = rfq->usd;
  q.collateral_asset = rfq->collateral_asset;
  q.maker = MAKER;
  q.nonce = next_nonce();
  q.price = my_price(*rfq);        // your model: USD per option, 1e18
  q.valid_until = now_s() + 60;    // SECONDS, > 30s out
  maker.send(sdk.quote_args(msg->id, q));
};

Process feed = sdk.spawn(sdk.connect_args("rfqs/" + ASSET));
std::thread feed_reader([&] { feed.read_lines(on_rfq); });
```

`maker` must exist before the feed delivers its first RFQ, so open `/maker`
first. Feeds are listen only; never `send` into one.

## 4. Follow the auction

Everything the api says to the maker arrives on `/maker`, under the RFQ id or
a fixed id:

```cpp
void on_maker(const std::string& line) {
  auto msg = JsonRpcResponse::parse(line);
  if (!msg) return;
  if (msg->id == "skill_issue") {                       // outbid
    if (auto n = QuoteNotification::from_json(*msg->result))
      requote_above(n->rfq_id, n->new_best);
  } else if (msg->id == "trade") {                      // you won, and it settled
    std::cout << "filled " << (*msg->result)["txHash"].as_string().value_or("") << "\n";
  } else if (msg->error) {  // a quote that does not lead, or a rejected command
    std::cerr << msg->id << " " << msg->error->message << " "
              << (msg->error->data ? msg->error->data->dump() : "") << "\n";
  } else {                  // "OK" for a leading quote, balances, positions…
    std::cout << msg->id << " " << msg->result->dump() << "\n";
  }
}
```

`skill_issue` and `trade` only reach a connection that has quoted at least
once. The error strings and what to do about each are in the
[protocol doc](../../../docs/v12.md#3-the-maker-quotes); a raise has to clear
the best by 10 bps ([auction rules](../../../docs/v12.md#4-the-auction)).

Run until you stop. Join the readers before the `Process`es go out of scope:

```cpp
feed.kill();
maker.kill();
feed_reader.join();
maker_reader.join();
```

## After the trade

```cpp
maker.send(sdk.positions_args(MAKER));
// opt an otoken in (true) or out (false) of redemption at expiry
maker.send(sdk.will_redeem_args(CHAIN_ID, MAKER, "0xotoken", true, next_nonce()));
// redeem expired otokens now: plain http, so run, not send
sdk.run(sdk.self_redeem_args(CHAIN_ID, next_nonce()));
```

## Taker

There are no builders for the taker commands, but `send` takes any arg list, so
a `/taker` connection takes them as the CLI documents them
([CLI README](../../cli/README.md)):

```cpp
Process taker = sdk.spawn(sdk.connect_args("taker"));
std::thread taker_reader([&] { taker.read_lines(on_taker); });
taker.send({"request", "--asset", ASSET, "--chain_id", std::to_string(CHAIN_ID), …});
// answered under id "request" with the winning quote (a Json); take it:
taker.send({"confirm", "--quote", winning.dump(), "--nonce", next_nonce()});
```

The taker approves its collateral to the margin pool first. `approve_args`
defaults the spender to the mmarket, so append the margin pool:

```cpp
auto args = sdk.approve_args(CHAIN_ID, amount, RPC_URL, collateral);
args.insert(args.end(), {"--spender", MARGIN_POOL});
sdk.run(args);
```

## Nonces

`NonceCounter` persists every nonce before handing it out, so a restart never
reuses one. Use one counter per key for quotes, transfers, redemptions and
confirmations alike, behind a lock when more than one thread draws from it.
