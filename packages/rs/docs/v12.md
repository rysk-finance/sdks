# V12 RFQ integration (Rust)

The websocket auction, as a Rust maker runs it. This page is the code;
[`docs/v12.md`](../../../docs/v12.md) is the protocol — the auction rules,
the error strings and the units — and each step below links back to it.

> Testnet (`Env::Testnet`) runs the strategies protocol, whose messages have a
> different shape. Everything here is what production (`Env::Mainnet`) runs.

## Setup

```rust
use std::error::Error;
use std::io::{BufRead, BufReader};
use std::process::ChildStdin;
use std::thread;
use std::time::{SystemTime, UNIX_EPOCH};
use ryskv12::{send, Env, JsonRpcResponse, NonceCounter, Quote, QuoteNotification, Request, Rysk, Transfer};

const MAKER: &str = "0x…";   // the address of PRIVATE_KEY
const ASSET: &str = "0x…";   // the underlying you make markets in
const USDC: &str = "0x…";    // the chain's strike asset
const CHAIN_ID: i64 = 8453;

let rysk = Rysk::new(Env::Mainnet, std::env::var("PRIVATE_KEY")?)?;
let mut nonces = NonceCounter::default(); // one per key, file backed: see Nonces below

fn now() -> i64 {
    SystemTime::now().duration_since(UNIX_EPOCH).unwrap().as_secs() as i64
}
```

The snippets run inside a `fn main() -> Result<(), Box<dyn Error>>`. The key
reaches the CLI through `RYSK_PRIVATE_KEY` in its environment, never argv. No
CLI yet? `rysk.setup()?` downloads one (unix only).

## 1. Fund the maker balance

Premiums come out of the balance deposited with Rysk, not the wallet
([protocol](../../../docs/v12.md#1-before-quoting-funds)). Approving is an
on-chain call, so it is a one-off process; the deposit goes over `/maker`.

```rust
let approve = rysk.execute(&rysk.approve_args(CHAIN_ID, "1000000000", RPC_URL, None))?.wait_with_output()?;
assert!(approve.status.success(), "{}", String::from_utf8_lossy(&approve.stderr));
```

```rust
let mut maker = rysk.execute(&rysk.connect_args("maker"))?;
let mut stdin = maker.stdin.take().unwrap();
let replies = BufReader::new(maker.stdout.take().unwrap());
thread::spawn(move || {
    for line in replies.lines().map_while(Result::ok) {
        on_maker(&line);
    }
});

send(&mut stdin, &rysk.transfer_args(&Transfer {
    user: MAKER.into(), asset: USDC.into(), amount: "1000000000".into(), chain_id: CHAIN_ID,
    is_deposit: true, // false withdraws
    nonce: nonces.next()?,
}))?;
send(&mut stdin, &rysk.balances_args(MAKER))?; // answered on on_maker
```

## 2. Listen for RFQs, 3. quote

One feed per asset, plus the one `/maker` connection. Each feed line is a
json-rpc message whose `id` is the RFQ id and whose `result` is the request
([protocol](../../../docs/v12.md#2-an-rfq-arrives)). Copy its terms into the
quote unchanged; only `price`, `nonce` and `valid_until` are yours
([protocol](../../../docs/v12.md#3-the-maker-quotes)).

```rust
fn on_rfq(rysk: &Rysk, maker: &mut ChildStdin, nonces: &mut NonceCounter, line: &str) -> Result<(), Box<dyn Error>> {
    let msg = JsonRpcResponse::from_json(line)?;
    // None on an error, or on a result that is not a request
    let Some(rfq) = msg.result_as::<Request>() else { return Ok(()) };
    let quote = Quote {
        price: my_price(&rfq),               // your model: USD per option, 1e18
        asset_address: rfq.asset, chain_id: rfq.chain_id, expiry: rfq.expiry,
        is_put: rfq.is_put, is_taker_buy: rfq.is_taker_buy.unwrap_or(false),
        strike: rfq.strike, quantity: rfq.quantity,
        usd: rfq.usd, collateral_asset: rfq.collateral_asset,
        maker: MAKER.into(),
        nonce: nonces.next()?,
        valid_until: now() + 60,             // SECONDS, > 30s out
        ..Default::default()
    };
    send(maker, &rysk.quote_args(&msg.id, &quote)?)?;
    Ok(())
}

// blocks for as long as the feed is up
rysk.execute_lines(&rysk.connect_args(&format!("rfqs/{ASSET}")), |line| {
    if let Err(e) = on_rfq(&rysk, &mut stdin, &mut nonces, line) {
        eprintln!("rfq: {e}");
    }
})?;
```

`execute_lines` hands each line to the closure on the calling thread, so
`/maker` must be open first; more assets means a thread per feed, sharing the
stdin and the counter behind a `Mutex`. Feeds are listen only; `execute_lines`
keeps their stdin, so nothing can be sent into one.

## 4. Follow the auction

Everything the api says to the maker arrives on `/maker`, under the RFQ id or
a fixed id:

```rust
fn on_maker(line: &str) {
    let Ok(msg) = JsonRpcResponse::from_json(line) else { return };
    if msg.id == "skill_issue" {                     // outbid
        if let Some(n) = msg.result_as::<QuoteNotification>() {
            requote_above(&n.rfq_id, &n.new_best);
        }
    } else if msg.id == "trade" {                    // you won, and it settled
        println!("filled {}", msg.result.unwrap_or_default()["txHash"]);
    } else if let Some(e) = msg.error {              // a quote that does not lead, or a rejected command
        eprintln!("{} {} {:?}", msg.id, e.message, e.data);
    } else {                                         // "OK" for a leading quote, balances, positions…
        println!("{} {:?}", msg.id, msg.result);
    }
}
```

`skill_issue` and `trade` only reach a connection that has quoted at least
once. Requoting from this thread means sharing the stdin and the counter with
it, behind an `Arc<Mutex<_>>`. The error strings and what to do about each are
in the [protocol doc](../../../docs/v12.md#3-the-maker-quotes); a raise has to
clear the best by 10 bps ([auction rules](../../../docs/v12.md#4-the-auction)).

Run until you stop: `execute_lines` returns when the feed's CLI exits, then

```rust
maker.kill()?; // disconnect
```

## After the trade

```rust
send(&mut stdin, &rysk.positions_args(MAKER))?;
// opt an otoken in (true) or out (false) of redemption at expiry
send(&mut stdin, &rysk.will_redeem_args(CHAIN_ID, MAKER, "0xotoken", true, &nonces.next()?))?;

```

## Taker

There are no builders for the taker commands, but `send` takes any arg list, so
a `/taker` connection takes them as the CLI documents them
([CLI README](../../cli/README.md)):

```rust
let mut taker = rysk.execute(&rysk.connect_args("taker"))?;
let mut orders = taker.stdin.take().unwrap(); // read taker.stdout as for /maker
let args = |a: &[&str]| a.iter().map(|s| s.to_string()).collect::<Vec<_>>();

send(&mut orders, &args(&["request", "--asset", ASSET, "--chain_id", &CHAIN_ID.to_string(), /* … */]))?;
// answered under id "request" with the winning quote (a serde_json::Value); take it:
send(&mut orders, &args(&["confirm", "--quote", &winning.to_string(), "--nonce", &nonces.next()?]))?;
```

The taker approves its collateral to the margin pool first. `approve_args`
defaults the spender to the mmarket, so append the margin pool:

```rust
let mut approve = rysk.approve_args(CHAIN_ID, amount, RPC_URL, Some(collateral));
approve.extend(["--spender".to_string(), MARGIN_POOL.to_string()]);
rysk.execute(&approve)?.wait()?;
```

## Nonces

`NonceCounter` persists every nonce before handing it out, so a restart never
reuses one; that write is why `next()` returns an `io::Result`. Use one counter
per key for quotes, transfers, redemptions and confirmations alike.
