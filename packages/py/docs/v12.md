# V12 RFQ integration (Python)

The websocket auction, as a Python maker runs it. This page is the code;
[`docs/v12.md`](../../../docs/v12.md) is the protocol — the auction rules,
the error strings and the units — and each step below links back to it.

> Testnet (`Env.TESTNET`) runs the strategies protocol, whose messages have a
> different shape. Everything here is what production (`Env.MAINNET`) runs.

## Setup

```python
import asyncio, json, os, time
from ryskV12.client import Rysk, Env
from ryskV12.models import JSONRPCResponse, Quote, Request, Transfer, is_request
from ryskV12.nonce import NonceCounter

MAKER = "0x…"        # the address of PRIVATE_KEY
ASSET = "0x…"        # the underlying you make markets in
USDC = "0x…"         # the chain's strike asset
CHAIN_ID = 8453

rysk = Rysk(Env.MAINNET, private_key=os.environ["PRIVATE_KEY"])
nonces = NonceCounter()  # one per key, file backed: see Nonces below
```

The key reaches the CLI through `RYSK_PRIVATE_KEY` in its environment, never
argv. No CLI yet? `Rysk(...).setup()` downloads one.

## 1. Fund the maker balance

Premiums come out of the balance deposited with Rysk, not the wallet
([protocol](../../../docs/v12.md#1-before-quoting-funds)). Approving is an
on-chain call, so it is a one-off process; the deposit goes over `/maker`.

```python
approve = rysk.execute(rysk.approve_args(CHAIN_ID, "1000000000", RPC_URL))
out, err = approve.communicate()
assert approve.returncode == 0, err
```

```python
maker = await rysk.execute_async(rysk.connect_args("maker"), on_maker)

rysk.send(maker, rysk.transfer_args(Transfer(
    user=MAKER, asset=USDC, amount="1000000000", chain_id=CHAIN_ID,
    is_deposit=True,  # False withdraws
    nonce=nonces.next(),
)))
rysk.send(maker, rysk.balances_args(MAKER))  # answered on on_maker
```

## 2. Listen for RFQs, 3. quote

One feed per asset, plus the one `/maker` connection. Each feed line is a
json-rpc message whose `id` is the RFQ id and whose `result` is the request
([protocol](../../../docs/v12.md#2-an-rfq-arrives)). Copy its terms into the
quote unchanged; only `price`, `nonce` and `validUntil` are yours
([protocol](../../../docs/v12.md#3-the-maker-quotes)).

```python
def on_rfq(line: bytes):
    msg = JSONRPCResponse.from_json(line)
    if msg.error or not is_request(msg.result):
        return
    rfq = Request.from_json(msg.result)
    rysk.send(maker, rysk.quote_args(msg.id, Quote(
        assetAddress=rfq.asset, chainId=rfq.chainId, expiry=rfq.expiry,
        isPut=rfq.isPut, isTakerBuy=bool(rfq.isTakerBuy),
        strike=rfq.strike, quantity=rfq.quantity,
        usd=rfq.usd, collateralAsset=rfq.collateralAsset,
        maker=MAKER,
        nonce=nonces.next(),
        price=my_price(rfq),                 # your model: USD per option, 1e18
        validUntil=int(time.time()) + 60,    # SECONDS, > 30s out
    )))

feed = await rysk.execute_async(rysk.connect_args(f"rfqs/{ASSET}"), on_rfq)
```

`maker` must exist before the feed delivers its first RFQ, so open `/maker`
first. Feeds are listen only; never `send` into one.

## 4. Follow the auction

Everything the api says to the maker arrives on `/maker`, under the RFQ id or
a fixed id:

```python
def on_maker(line: bytes):
    msg = JSONRPCResponse.from_json(line)
    if msg.id == "skill_issue":              # outbid
        n = msg.result                       # rfqId, newBest, yours, …
        requote_above(n["rfqId"], n["newBest"])
    elif msg.id == "trade":                  # you won, and it settled
        print("filled", msg.result["txHash"])
    elif msg.error:                          # a quote that does not lead, or a rejected command
        print(msg.id, msg.error.message, msg.error.data)
    else:                                    # "OK" for a leading quote, balances, positions…
        print(msg.id, msg.result)
```

`skill_issue` and `trade` only reach a connection that has quoted at least
once. The error strings and what to do about each are in the
[protocol doc](../../../docs/v12.md#3-the-maker-quotes); a raise has to clear
the best by 10 bps ([auction rules](../../../docs/v12.md#4-the-auction)).

Run until you stop:

```python
await maker.wait()      # or feed.terminate(); maker.terminate()
```

## After the trade

```python
rysk.send(maker, rysk.positions_args(MAKER))
# opt an otoken in (True) or out (False) of redemption at expiry
rysk.send(maker, rysk.will_redeem_args(CHAIN_ID, MAKER, "0xotoken", True, nonces.next()))
# redeem expired otokens now: plain http, so execute, not send
rysk.execute(rysk.self_redeem_args(CHAIN_ID, nonces.next()))
```

## Taker

There are no builders for the taker commands, but `send` takes any arg list, so
a `/taker` connection takes them as the CLI documents them
([CLI README](../../cli/README.md)):

```python
taker = await rysk.execute_async(rysk.connect_args("taker"), on_taker)
rysk.send(taker, ["request", "--asset", ASSET, "--chain_id", str(CHAIN_ID), …])
# answered under id "request" with the winning quote; take it:
rysk.send(taker, ["confirm", "--quote", json.dumps(winning), "--nonce", nonces.next()])
```

The taker approves its collateral to the margin pool first. `approve_args`
defaults the spender to the mmarket, so append the margin pool:

```python
rysk.execute(rysk.approve_args(CHAIN_ID, amount, RPC_URL, collateral) + ["--spender", MARGIN_POOL])
```

## Nonces

`NonceCounter` persists every nonce before handing it out, so a restart never
reuses one. Use one counter per key for quotes, transfers, redemptions and
confirmations alike.
