# V12 RFQ integration (TypeScript)

The websocket auction, as a TypeScript maker runs it. This page is the code;
[`docs/v12.md`](../../../docs/v12.md) is the protocol — the auction rules,
the error strings and the units — and each step below links back to it.

> Testnet (`Env.TESTNET`) runs the strategies protocol, whose messages have a
> different shape. Everything here is what production (`Env.MAINNET`) runs.

## Setup

```ts
import Rysk, { Env, NonceCounter } from "ryskv12";
import { isQuoteNotification, isRequest, type JSONRPCResponse, type HexString } from "ryskv12/models";

const MAKER: HexString = "0x…";   // the address of PRIVATE_KEY
const ASSET: HexString = "0x…";   // the underlying you make markets in
const USDC: HexString = "0x…";    // the chain's strike asset
const CHAIN_ID = 8453;

const rysk = new Rysk(Env.MAINNET, process.env.PRIVATE_KEY!);
const nonces = new NonceCounter();  // one per key, file backed: see Nonces below

const parse = (line: Buffer) => JSON.parse(line.toString()) as JSONRPCResponse;
```

The key reaches the CLI through `RYSK_PRIVATE_KEY` in its environment, never
argv. No CLI yet? The package's postinstall downloads one to `./ryskV12`; the
third constructor argument points elsewhere.

## 1. Fund the maker balance

Premiums come out of the balance deposited with Rysk, not the wallet
([protocol](../../../docs/v12.md#1-before-quoting-funds)). Approving is an
on-chain call, so it is a one-off process; the deposit goes over `/maker`.

```ts
const approve = rysk.execute(rysk.approveArgs(CHAIN_ID, "1000000000", RPC_URL));
approve.on("stderr", (d) => process.stderr.write(d));
approve.on("close", (code) => { if (code !== 0) throw new Error(`approve exited ${code}`); });
```

```ts
const maker = rysk.execute(rysk.connectArgs("maker"));
maker.on("message", onMaker);

maker.send(rysk.transferArgs({
  user: MAKER, asset: USDC, amount: "1000000000", chain_id: CHAIN_ID,
  is_deposit: true,  // false withdraws
  nonce: nonces.next(),
}));
maker.send(rysk.balancesArgs(MAKER));  // answered on onMaker
```

## 2. Listen for RFQs, 3. quote

One feed per asset, plus the one `/maker` connection. Each feed line is a
json-rpc message whose `id` is the RFQ id and whose `result` is the request
([protocol](../../../docs/v12.md#2-an-rfq-arrives)). Copy its terms into the
quote unchanged; only `price`, `nonce` and `validUntil` are yours
([protocol](../../../docs/v12.md#3-the-maker-quotes)).

```ts
function onRfq(line: Buffer) {
  const msg = parse(line);
  if (msg.error || !isRequest(msg.result)) return;
  const rfq = msg.result;
  maker.send(rysk.quoteArgs(msg.id, {
    assetAddress: rfq.asset, chainId: rfq.chainId, expiry: rfq.expiry,
    isPut: rfq.isPut, isTakerBuy: Boolean(rfq.isTakerBuy),
    strike: rfq.strike, quantity: rfq.quantity,
    usd: rfq.usd, collateralAsset: rfq.collateralAsset,
    maker: MAKER,
    nonce: nonces.next(),
    price: myPrice(rfq),                              // your model: USD per option, 1e18
    validUntil: Math.floor(Date.now() / 1000) + 60,   // SECONDS, > 30s out
  }));
}

const feed = rysk.execute(rysk.connectArgs(`rfqs/${ASSET}`));
feed.on("message", onRfq);
```

`maker` must exist before the feed delivers its first RFQ, so open `/maker`
first. Feeds are listen only; never `send` into one.

## 4. Follow the auction

Everything the api says to the maker arrives on `/maker`, under the RFQ id or
a fixed id:

```ts
function onMaker(line: Buffer) {
  const msg = parse(line);
  if (msg.id === "skill_issue" && isQuoteNotification(msg.result)) {  // outbid
    requoteAbove(msg.result.rfqId, msg.result.newBest);
  } else if (msg.id === "trade") {                                     // you won, and it settled
    console.log("filled", (msg.result as { txHash: string }).txHash);
  } else if (msg.error) {                    // a quote that does not lead, or a rejected command
    console.log(msg.id, msg.error.message, msg.error.data);
  } else {                                   // "OK" for a leading quote, balances, positions…
    console.log(msg.id, msg.result);
  }
}
```

`skill_issue` and `trade` only reach a connection that has quoted at least
once. The error strings and what to do about each are in the
[protocol doc](../../../docs/v12.md#3-the-maker-quotes); a raise has to clear
the best by 10 bps ([auction rules](../../../docs/v12.md#4-the-auction)).

Run until you stop:

```ts
maker.on("close", (code) => console.log("maker exited", code));  // or feed.close(); maker.close()
```

## After the trade

```ts
maker.send(rysk.positionsArgs(MAKER));
// opt an otoken in (true) or out (false) of redemption at expiry
maker.send(rysk.willRedeemArgs(CHAIN_ID, MAKER, "0xotoken", true, nonces.next()));
// redeem expired otokens now: plain http, so execute, not send
rysk.execute(rysk.selfRedeemArgs(CHAIN_ID, nonces.next()));
```

## Taker

There are no builders for the taker commands, but `send` takes any arg list, so
a `/taker` connection takes them as the CLI documents them
([CLI README](../../cli/README.md)):

```ts
const taker = rysk.execute(rysk.connectArgs("taker"));
taker.on("message", onTaker);
taker.send(["request", "--asset", ASSET, "--chain_id", String(CHAIN_ID), …]);
// answered under id "request" with the winning quote; take it:
taker.send(["confirm", "--quote", JSON.stringify(winning), "--nonce", nonces.next()]);
```

The taker approves its collateral to the margin pool first. `approveArgs`
defaults the spender to the mmarket, so append the margin pool:

```ts
rysk.execute([...rysk.approveArgs(CHAIN_ID, amount, RPC_URL, collateral), "--spender", MARGIN_POOL]);
```

## Nonces

`NonceCounter` persists every nonce before handing it out, so a restart never
reuses one. Use one counter per key for quotes, transfers, redemptions and
confirmations alike.
